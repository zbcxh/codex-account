# 采集器版本上报

正式采集器在单轮及常驻模式共用的正常上报入口附加以下可选字段，服务端随每个额度报告窗口存储；不增加网络请求。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `collector_version` | string / null | 采集器自身发布版本，最长64字符 |
| `collector_build` | string / null | 编译时构建编号，最长96字符 |
| `collector_sha256` | string / null | 实际运行采集器 EXE 的64位十六进制 SHA-256 |

`cli_version` 仍表示 Codex 官方程序版本，与上述字段无关。版本和构建编号只允许 ASCII 字母、数字及 `.+_-`，首字符必须是字母或数字。非法元数据返回400 `bad_collector_metadata`；摘要统一存为小写。

`client-compiled/build.ps1` 支持 `-Version`（默认 `1.0.0`）和 `-BuildId`（默认 UTC 编译时间，格式 `yyyyMMddTHHmmssfffZ`），写入程序集属性。构建输出包含生成的 `CollectorAssemblyInfo.cs`，它不是客户端分发必需文件。未使用正式构建脚本的测试程序集不伪造正式版本。

程序摘要每个进程计算一次；读取失败保持 null，不中断额度上报。该字段是设备自报信息，用于定位程序版本，不等于服务端验签或可信安装证明。

报告入队时保留当时程序标识，历史补传和重放不改写元数据。`GET /api/state` 的 `machines[]` 返回三个同名字段，对应设备当前报告；迟到历史报告不替换当前报告。旧库启动时补充 nullable 列，旧报告和未升级采集器保持未知。若更新后的正常报告未提供元数据，显示未知，不沿用旧版本冒充当前安装。

设备详情分别显示 Codex 版本、采集器版本、构建编号和完整程序摘要。修改源码和构建不会自动安装设备采集器；旧设备需升级后才能上报这些字段。管理权限、设备令牌和现有迁移协议保持原有语义。
