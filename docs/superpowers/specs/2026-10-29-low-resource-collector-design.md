# 低配电脑常驻采集器设计草案

状态：2026-10-29 用户批准实现；已形成候选及隔离测试，未安装、部署或启用真实常驻采集。

## 目标与范围

用户选择常驻低负载模式，优先减少吴工电脑的CPU启动峰值和重复初始化，接受稳定运行约200MB、预计启动峰值在300MB以内。本文预算明确按MiB计算，统计采集器及其专属官方进程树；不计入、更不操作其他正常桌面版进程。

尚未在目标电脑实测，CPU是优先调查方向，不能据SSD类型断言其他资源绝无影响。保留禁用任务，不自动安装、启用、真实采集、重启正式服务、部署或推送。

## 已选方案与通信依据

采用独立常驻低负载入口，兼容现有C#/.NET Framework环境，保留原短进程模式，不替换所有设备。

不接管桌面版已有实例，不依赖HTTP接口或未公开监听地址。当前`QuotaPrototype.Collect`已自行启动`codex.exe app-server --disable plugins`并通过stdin/stdout调用`initialize`、`account/read`和`account/rateLimits/read`。常驻模式持续持有自有实例的这条通信通道。

每轮仍执行“读取账号→读取额度→再次读取账号”，身份三方一致才上报。只复用连接，不缓存上轮身份结论冒充当前身份。每轮启动并限CPU仍重复初始化，用户本次未选；复用桌面版缺少已核实的接入方式，不采用。

## 资源策略与实现建议

本轮按以下默认策略实现；仅验证合成进程，不代表真实官方版本或目标电脑已经达标。具体实现边界见 docs/LOW-RESOURCE-COLLECTOR.md。

| 项目 | 建议值与行为 |
| --- | --- |
| CPU | 外层Windows Job包含控制进程及全部后代，默认硬限额5%，本机允许1至10%；内层Job仅负责会话回收 |
| 启动内存 | 整个采集树预算300MiB，启动期也受CPU限制，不允许无约束启动 |
| 稳定内存 | 初始化后允许30秒收敛到200MiB以内，无法收敛或随后超限则回收会话并退避 |
| 统计口径 | 以合计私有提交量为预算主指标，另记录工作集；不强制清空工作集伪装低占用 |
| 超时 | 启动120秒、单轮查询60秒；限CPU后不能机械沿用现有25秒总时限 |
| 失败保护 | 5、15、30分钟递增退避；连续3次初始化或资源失败后暂停，等待显式恢复，不反复冷启动 |
| 采集周期 | 沿用设备确认的实际上报周期，内部定时器按周期唤醒，空闲等待事件 |

CPU硬限额作用于专属Job；若控制进程不在该Job，也必须计入整树内存监测和超限退出。200/300MiB是整树验收预算，不能在实测前承诺系统任意瞬间均不会超出。官方程序初始化若需要更多内存，则判为当前预算不适配并暂停，不自动提高限额。

## 生命周期与安全约束

- 在官方进程执行初始化前建立约束。低配模式采用挂起创建、绑定Job后恢复等可验证方式，避免当前Process.Start到绑定之间的峰值窗口；限制或绑定失败即退出，不放行无约束进程。
- 持有设备采集锁保证单例，阻止短进程入口并发采集；安装器不能覆盖尚未停止的常驻程序。
- stdout持续排空，通知与响应分离；请求ID在会话内唯一，行、缓冲及待处理响应数量有上限。stderr固定缓冲排空，不缓存完整日志。
- 身份不一致、超时、进程退出或资源状态无法确认时，本轮失败关闭；只回收自己创建的进程树。超时销毁会话，迟到响应不能进入下一轮。
- 正常实例在预算内持续复用，不通过固定频率重启再次制造CPU峰值。
- 不读取auth.json或历史会话猜测当前账号，不执行登录、切号或插件持久管理。

## 兼容与安装边界

沿用现有client_id、DPAPI令牌、地址和可靠队列，不创建第二个设备身份。复用幂等、满队列恢复、迁移证明及历史响应不应用配置等规则。

常驻的实际周期来自内部定时器，不能读取旧任务重复触发器冒充实际值；调度成功后才按原协议确认。服务端仍按实际周期加120秒宽限判断在线。修改周期只调整等待间隔，不重启官方实例。

资源参数先仅由本机控制，不扩展远程执行能力。常驻安装需显式选择并处理原任务两分钟执行上限、重复触发器和单例退出；代码交付阶段不对真实任务应用变更。

## 验证与交付

先以合成RPC进程、CPU负载、可控内存增长、任务替身、临时目录及回环服务测试。覆盖一次初始化多轮查询、账号切换失败关闭、响应隔离、流排空、启动/稳定预算、限制失败关闭、退避暂停、锁冲突、整树回收、周期确认、队列/身份保持和原短进程回归。

合成测试只能证明机制。后续获准后才实测官方只读查询，记录启动峰值、稳定私有内存/工作集、整树CPU、采集耗时与长期增长，至少包含多个20分钟周期，注明硬件、官方版本和时长。未实测不宣称200/300MiB达标或不卡顿。
