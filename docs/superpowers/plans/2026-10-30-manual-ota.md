# 管理员手动 OTA 实施计划

> 执行方式：在当前会话按任务逐项实现，使用 superpowers:executing-plans；每项先补充失败测试，再实现并验证。

**目标：** 管理员选择设备及可信版本后创建升级任务，客户端安全替换采集器，失败可回滚。

**架构：** 复用现有管理员鉴权、设备令牌和正常上报通道。独立升级器通过固定任务在常驻资源 Job 外运行；签名清单固定信任根，持久阶段日志控制替换和恢复。

**技术栈：** Node、SQLite、Vue/TypeScript、C# 5、Windows PowerShell 5.1。

**设计依据：** `docs/superpowers/specs/2026-10-29-manual-ota-design.md`。

## 全局约束

- 不访问真实数据库、配置、身份令牌或上报队列，不启用吴工任务，不部署或推送。
- RSA-3072/SHA-256、PKCS#1 v1.5；仅临时测试密钥，测试信任根不得进入交付包。
- 单个 win-x64 EXE 最大20MiB；同源固定下载路径、拒绝重定向、保留证书检查。
- 保留 client_id、DPAPI、服务地址、周期、运行模式、禁用状态及暂停标记。
- 所有新增和修改函数补齐中文功能、参数和返回值注释。

## 重点验证

- 签名正确但清单重复字段、错误类型或版本倒退必须拒绝。
- 上报历史队列响应不能触发 OTA，重复领取不得重复替换。
- 断电、文件占用和第三方任务变化必须保留证据并安全停止或精确回滚。
- 禁用或暂停设备不得因升级被启用。
- 升级器与新常驻进程的生命周期交接不得叠加官方进程启动。

## 任务1：确认源码接口并固定协议

- [ ] 完整加载当前 AOCI；检查 CodeGraph 状态并定位上报、管理员鉴权、任务安装和生命周期锁实现。
- [ ] 阅读上述设计涉及的源码，确定独立领域文件和既有接口的最小接入点。
- [ ] 编写 OTA 协议文档，固定清单原始字节签名、能力字段、任务状态、错误码及时间单位。

## 任务2：服务端发布与升级任务

- [ ] 在临时 SQLite 编写发布验签、设备归属、旧客户端、幂等和口令轮换测试，确认先失败。
- [ ] 新增独立 OTA 领域模块及表结构；接入管理员发布列表/任务创建/状态查询、设备领取/确认和有界下载。
- [ ] 正常报告携带可选能力；只在当前请求响应传递任务，禁止历史响应触发。
- [ ] 运行领域测试及现有鉴权、配对和报告相关回归。

## 任务3：客户端可信下载及独立升级器

- [ ] 使用临时密钥和合成 EXE 编写错误签名、大小、过期、平台、降级、重放测试并确认失败。
- [ ] 新增验签、严格清单解析和流式下载模块，固定本地信任根；无可信根时明确报告不可升级。
- [ ] 实现固定升级任务、私有状态与停止信号、生命周期锁交接及五分钟退出边界。
- [ ] 实现持久阶段日志、摘要复查、File.Replace、只读健康检查、唯一上一版本回滚及断电恢复。
- [ ] 对每个持久阶段注入故障；验证未知进程/任务、文件冲突、并发、暂停和禁用状态、身份/令牌/队列字节保持。
- [ ] 验证升级器退出后新采集器才启动官方进程；测量合成升级窗口资源。

## 任务4：管理面板

- [ ] 阅读前端行为约定和设计文档，补充 API 类型及设备能力/升级状态。
- [ ] 实现选择版本和设备、明确确认、逐设备结果及错误展示；不自动追随最新版。
- [ ] 增加领域测试，运行类型检查、测试、构建并以合成页面验证交互。

## 任务5：收尾及交付

- [ ] 完成相关隔离回归及差异审查，记录本次实际验证结果。
- [ ] 最终源码稳定后维护 AOCI，按返回批次完成更新及对齐核验；同步 CodeGraph。
- [ ] 从当前源码在独立目录重新构建，白名单打包 EXE、升级器、必要安装脚本、说明和清单。
- [ ] 记录 Git 版本、未提交状态、源码与产物 SHA-256；核查压缩包不含凭据、配置、运行数据、数据库、测试信任根或测试驱动。
- [ ] 交付包明确区分已实现能力与尚未配置正式信任根的状态；不宣称真实 OTA 或吴工电脑验收成功。
